**Date:** 2026-08-09
**Scope:** Full workspace (frp-core, frp-server, frp-client, frp-vnet, frps, frpc)

## Dimension 1: Async I/O & High-Concurrency Flow Control

### 1.1 Zero-Copy Forwarding

| Site | Mechanism | Buffer | Verdict |
|------|-----------|--------|---------|
| `frp-server/src/control/bridge.rs:535` | `bridge_splice` (Linux splice(2)) | kernel pipe 64 KiB | **Optimal** — zero-copy, AsyncFd epoll, no `spawn_blocking` |
| `frp-client/src/proxy.rs:432` | `bridge_splice` (Linux splice(2)) | kernel pipe 64 KiB | **Optimal** |
| `frp-server/src/control/bridge.rs:547,572,921` | `copy_bidirectional_with_sizes` | 32 KiB each dir | **Good** — sized from `BUFFER_SIZE` LazyLock |
| `frp-client/src/proxy.rs:472` + 6 plugin sites | `copy_bidirectional_with_sizes` | 32 KiB | **Good** |
| `frp-core/src/bridge.rs:202,288` | `PoolGuard::acquire()` + manual read/write | 32 KiB pooled | **Optimal** — zero-alloc on hot path |
| `frp-core/src/http_client.rs:807,916` | `copy_bidirectional` (default) | 8 KiB | **Minor** — CONNECT/origin tunnel, short-lived |

**Bridge buffer pool** (`frp-core/src/buffer_pool.rs`): 32 KiB chunks, crossbeam `ArrayQueue` (lock-free MPMC), 128 max (4 MiB), RAII `PoolGuard` recycles on drop. Recycled buffers skip 32 KiB `memset` via `resize` guard. Zero allocation per chunk after warmup.

**Finding A5 (P3):** `http_client.rs` CONNECT tunnels use tokio 8 KiB default. Bump to 32 KiB via `copy_bidirectional_with_sizes`. Low impact — these are short-lived plugin connections.

### 1.2 WebSocket Frame Handling

Manual RFC 6455 (`frp-core/src/transport/websocket.rs`). Tungstenite removed 2026-08-09.

- `build_frame_into`: writes into caller's `write_buf`, `clear()` + `reserve(len + 14)` — capacity reused across bridge chunks. Zero per-frame allocation.
- Read path: `raw_payload_buf` reused via `mem::take` + return-to-field. `to_vec()` only on rare frame-payload-overflow.
- Ping/Pong: stack `[u8; 128]` pong buffer. No heap allocation.
- Frame cap: `MAX_WS_FRAME_PAYLOAD = 66 KiB`. Oversized → `InvalidData` reject.

**Verdict:** Excellent. No per-frame heap allocation. Stack buffers for control frames. Capacity reuse for data frames.

### 1.4 `select!` Bias

- **Main control loop** (`control/mod.rs:262`): `tokio::select!` without `biased;` — deliberately fair. Regression test at line 483 asserts this.
- **Cancel-first paths**: `visitor.rs:1107,1283`, `work_conn.rs:445,594,816,972,1025`, `control/bridge.rs:279,330` — `biased;` correct for cancel/shutdown-first.
- **Comment-documented unbiased**: `visitor.rs:1149,1465` — explicitly NOT biased to prevent starvation.

**Verdict:** Excellent. Biased where correct (cancel-first), fair where needed (main loop). Regression-tested.

## Dimension 2: Long Connection Management & Memory Footprint

### 2.1 TCP Keepalive & Heartbeat

| Setting | Server | Client | Notes |
|---------|--------|--------|-------|
| `TCP_NODELAY` | Every accept | Every dial | `set_nodelay` on raw TcpStream before wrapping |
| `SO_KEEPALIVE` | 7200s | 0 (off) | Go parity |
| Yamux keepalive | 30s scan, 90s dead | Same | `ActivityState` AtomicBool dead-conn detect |
| QUIC keepalive | 10s idle | Same | quinn param |
| App heartbeat | 30s Ping, 90s timeout | Same | `select!` timer arm, NOT spawned task |

**Verdict:** Correct. Yamux PING/PONG is primary liveness signal. Heartbeat is zero-spawn timer arm. With `tcp_mux` on (default), app heartbeat disabled (Go parity) — yamux keepalive is sole liveness mechanism.

**Finding A7 (P4):** Server TCP keepalive = 7200s (2h). Consider 300s default for non-yamux deployments. Go parity but conservative 5min keepalive is still safe.

### 2.2 `tokio::spawn` Audit

153 spawn sites across 40 files. Key per-connection breakdown:

| Path | Spawns per conn | Bounded by |
|------|----------------|------------|
| Server main accept | 1 `spawn_boxed` | `conn_semaphore` (when configured) |
| Server vhost accept | 1 | `conn_semaphore` |
| Server TcpMux accept | 1 per stream | `conn_semaphore` |
| Server SSH channel | 1-2 | per-session |
| Bridge (encrypted) | 0 | `tokio::join!` — zero extra tasks |
| Bridge (plain) | 0 | `tokio::join!` — zero extra tasks |
| Bridge (UDP) | 1-2 per direction | per-proxy |
| Client work conn | 1 per ReqWorkConn | **Unbounded** (Go parity) |
| Client visitor accept | 1 per STCP/XTCP conn | **No cap** |
| Client UDP session | 1 per remote | per-proxy |

**Finding A2 (P2):** Default `max_connections = None` (unlimited, `config/server.rs:310`). Connection flood can exhaust memory through unbounded task spawning. Set conservative default (1024).

### 2.3 Connection Pooling

`control/pool.rs`: `assign_or_queue` — pool hit → bridge + ReqWorkConn replenish. Pool miss → ReqWorkConn + queue. Pool size: `poolCount + 10` (Go parity). Pending cap: 256. Timeout: 10s (`user_conn_timeout`). Idle expiry: removed (Go parity).

**Verdict:** Good. Pool pre-warms. Request queue bounded. Idle removal matches Go.

### 2.4 Buffer Pool

`crossbeam_queue::ArrayQueue<Vec<u8>>`, 128 max (4 MiB total). Lock-free MPMC. `PoolGuard` RAII — returns buffer on drop even on early `break`/`return`. Recycled buffers skip 32 KiB `memset`.

**Verdict:** Excellent. Zero contention, zero leak risk, zero alloc on hot path after warmup.

## Dimension 3: Multi-Thread Lock Contention & Concurrency

### 3.1 Hot-Path Data Structures

| Structure | Type | Hot Path | Verdict |
|-----------|------|----------|---------|
| `run_id_to_ctl_tx` | `Arc<DashMap<String, ControlTx>>` | Every work-conn dispatch | **Optimal** — sharded lock-free reads |
| `ProxyManager.proxies` | `DashMap<String, Arc<ProxyInfo>>` | Every NewWorkConn/NewVisitorConn | **Optimal** |
| `reloadable` | `Arc<std::sync::RwLock<ReloadableState>>` | Every dispatch (read auth/ports) | **Good** — blocking read, write only on SIGUSR1 |
| `tls_acceptor` | `Arc<std::sync::RwLock<Option<TlsAcceptor>>>` | Every TLS handshake | **Good** |
| `VhostManager` | Single `tokio::sync::RwLock` | Every HTTP/HTTPS request | **Adequate** — read-mostly, `has_location_routes` AtomicBool fast-gate |
| `accept_rate_limiter` | `AtomicU64` CAS | Every accept | **Optimal** — lock-free |
| `pool_stats` | `AtomicI64` | Every pool op | **Optimal** |
| `PoolMetrics` | `AtomicU64` hits/misses/drops | Every pool op | **Optimal** |

### 3.2 Client Control Writer — Real Bottleneck

`frp-client/src/service.rs`: `BoxedWriteHalf` behind `tokio::sync::Mutex`, guard held for full `write_msg().await`. Serializes ALL control messages across concurrent tasks. One stalled write blocks every other control message (Ping, NewProxy, CloseProxy, NatHoleClient/Resp/Visitor).

**Finding A1 (P1):** Replace with mpsc channel + dedicated writer task. Server already uses this pattern (`internal_tx` channel → control handler select loop). A single `mpsc::Sender<FrpMessage>` + spawned writer eliminates the lock and provides natural backpressure.

### 3.3 `std::sync::Mutex` vs `tokio::sync::Mutex`

Correct everywhere:
- `std::sync::Mutex`: short sync sections, never across `.await`. Used for `group_counters`, `run_mu_map`, client maps, `UdpSessionTable`, mux `Connection`.
- `tokio::sync::Mutex`: held across `.await`. Used for `login_throttle`, `LAST_TRAFFIC`, lifecycle `run_mu`, client `proxy_info_map`, vnet `controller`.

**Zero violations** of `std::sync::MutexGuard` crossing `.await`.

### 3.4 Channel Capacities

All production channels bounded. No `unbounded_channel()` outside test code. Ranges from `mpsc(1)` to `mpsc(1024)`.

### 4.2 Panic Risk Analysis

Precise counts (non-test production code only, `#[cfg(test)]`/`mod tests`/`tests/` dirs excluded):

| Category | Count | Risk |
|----------|-------|------|
| `.unwrap()` production | **1** | `visitor.rs:1087` — parses hardcoded `"0.0.0.0:0"` literal. Cannot fail. Safe. |
| `.expect()` production | **77** | All internal-state invariants, length-guarded slices, or `Option::is_some`-guarded patterns. Zero reachable from untrusted wire input. |
| `panic!()` / `todo!()` / `unimplemented!()` | **0** | None in production code |
| `unreachable!()` | **5** | All guarded invariants (base64 chunks_exact remainder, KCP cmd validation, IPv4 guard, family equality check) |
| Array/slice `[index]` on wire data | **0 unguarded** | All protocol parsers (V1/V2, KCP+FEC, STUN, XTCP, yamux, SOCKS5, SNI, SSH) bounds-check before indexing |

**Highest-concentration expect sites:**

| File | Count | Pattern |
|------|-------|---------|
| `cipher_stream.rs` | 14 | CFB state machine: IV-before-decrypt, cfb-before-encrypt. Internal invariants. |
| `metrics/prom.rs` | 11 | Static `Lazy` metric definitions. Constant strings. Cannot fail. |
| `client/store.rs` | 11 | `Mutex::lock().expect("poisoned")` — fires only after prior panic unwound thread |
| `client/service.rs` | 6 | `.take().expect("run() called twice?")` + `is_some_and` guard |
| `kcp/protocol.rs` | 5 | Read helpers guarded by `>= KCP_OVERHEAD` loop |

**Verdict: P0 (crash-on-wire): none. P1 (crash-on-config): none.** All protocol parsers bounds-check network data before slicing/indexing. The 77 expects are internal invariants — trigger = programmer error, not external input. ~35 are P2 (crash-on-shutdown/internal): Mutex poison, Option::take-once, guarded unreachable. These only fire after a prior logic bug.

### 4.3 Error Propagation

All I/O errors use `tracing::debug!`/`warn!` + graceful break/return. No swallowed errors in the hot path. Dashboard API returns structured errors. Plugin paths propagate to callers.

### 5.3 Allocator

`mimalloc` opt-in only. Not default — measured no ≥5% throughput gain (2026-08 A/B). Correctly mutually exclusive with `mem-profile`.

**Finding A8 (P4):** Consider `mimalloc` as default for release. A/B tested throughput only — memory fragmentation over hours/days was not measured. Network proxy workload pattern benefits from mimalloc's fragmentation resistance. Cost: ~+200 KB.

## What's Already Excellent

1. **Zero-copy splice(2)** on Linux with AsyncFd (not `spawn_blocking`). Best-in-class.
2. **Buffer pool** — lock-free crossbeam ArrayQueue + RAII PoolGuard. Zero alloc on hot path.
3. **All channels bounded** — no `unbounded_channel()` in production. Drop-on-full = Go parity.
4. **DashMap on hot paths** — `run_id_to_ctl_tx` and `ProxyManager.proxies` sharded, lock-free reads.
5. **`select!` discipline** — biased where cancel-first, fair where needed, regression-tested.
6. **No `MutexGuard` across `.await`** with `std::sync::Mutex`. Zero violations.
7. **Release profile** — `opt-level=z` + `lto=fat` + `codegen-units=1` + `strip=true` + `panic=abort`. Optimal.
8. **WebSocket framing** — zero per-frame allocation, stack control-frame buffers, `build_frame_into` caller-buffer reuse.
9. **Heartbeat zero-spawn** — `select!` timer arm, not a spawned task. No task churn.
10. **`spawn_boxed`** type erasure — prevents monomorphization bloat in `tokio::spawn`.
11. **Unsafe hygiene** — 49 unsafe blocks + 4 unsafe fns, all with `// SAFETY:` comments (one nit: `http_client.rs:69` missing comment). All are FFI or standard patterns. Wire-data parsers all bounds-check before indexing — zero unguarded `[index]` on network input.
12. **Lock ordering documented** — `ProxyManager` has explicit lock order comment (`proxy.rs:297-315`).
13. **CI CI binary size note** — `lto=false opt-level=2` in CI documented in CLAUDE.md, not confused with release profile.
14. **yamux keepalive** — `ActivityState` AtomicBool dead-conn detection with `MAX_IDLE_KEEPALIVE_TICKS = 3`.
15. **Encrypted bridge IV flush** — `CipherWriter` eagerly flushes IV to prevent dual-CipherWriter deadlock (`bridge.rs:504-507`).

## Audit Methodology

- **Pass 1:** 5 parallel dimension-specialized agents investigating all source files
- **Pass 2:** Direct adversarial cross-reference — read every flagged file, verify agent claims against source
- **Pass 3:** Synthesis — categorize by severity, assign priorities, eliminate false positives, write report

Agents dispatched: async I/O patterns, memory/connection management, lock contention/concurrency, panic/unsafe sites, build config/binary size. Non-trivial cross-references: lock ordering, channel bounds, unwrap categorization against `#[cfg(test)]` boundaries, feature flag propagation across crates.
