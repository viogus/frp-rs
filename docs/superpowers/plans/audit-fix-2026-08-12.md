## Task 1 — Server deadlock: used_ports ↔ port_reservations lock inversion [HIGH]

**Files:** `frp-server/src/control/proxy_ops.rs`

**Finding:** `unregister_control` (every control disconnect/supersession) holds `used_ports.write()` across `port_reservations.write()` inserts (~lines 1300-1316). `allocate_proxy_port`'s TCP reservation path holds `port_reservations.write()` while awaiting `used_ports.read()` (~lines 179-193). Reconnect-during-cleanup interleaving deadlocks both; stuck cleanup owns `used_ports` write lock so the wedge is service-wide until restart.

**Fix:**
1. In `allocate_proxy_port`: never hold `port_reservations` across a `used_ports` acquisition — clone the reserved port, drop the guard, then check `used_ports`.
2. In `unregister_control`: drop `used_ports` guard before any `port_reservations` / `group_len` / `remove_group` await (the existing `drop(ports)` at ~line 1326 shows the pattern — apply it to every such cross-lock await).

**Test:** Existing proxy registration tests must pass. Add a regression test if feasible: concurrent register + unregister of same run_id must not hang (may be hard to make deterministic — a documented test attempt is acceptable, but at minimum existing suite must pass).

## Task 2 — Server slowloris: unbounded first-read phases [HIGH ×2]

**Files:** `frp-core/src/mux.rs`, `frp-server/src/handlers/transport.rs`, `frp-server/src/service.rs`

**Findings:**
1. `server_mux` (mux.rs:387) waits for the first yamux frame with no deadline; keepalive/idle-kill driver spawns only AFTER first stream arrives. Six call sites (transport.rs:358, 462, 763, 931, 1115, 1293). Silent client parks task+fd+conn_semaphore permit indefinitely; 512 silent sockets block all new clients (default max_connections=512). Go frp bounds with connReadTimeout=10s.
2. Post-handshake V2-magic `read_exact` (7 bytes) has no deadline at transport.rs:282, 556, 693, 844 and service.rs:409 (dedicated WS listener). Same permanent-hold class.

**Fix:** Wrap first-yamux-stream accept and each post-handshake magic read in `tokio::time::timeout_at(accept_deadline, ...)` — the existing `accept_deadline` (10s) pattern already used at transport.rs:240 and dispatch.rs:958. The timeout must cover the whole initial read phase.

**Tests:** Existing KCP/WS/tcpmux integration tests pass. `scripts/compat-test.sh --verbose` (protocol/transport change).

## Task 3 — Server control-plane correctness [MEDIUM ×7]

**Files:** `frp-server/src/control/proxy_ops.rs`, `frp-server/src/control/proxy.rs`, `frp-server/src/proxy.rs`, `frp-server/src/tcpmux.rs`

1. **client_ports_used inflated** (proxy_ops.rs:1031-1038): counter bumped for every proxy type incl. stcp/xtcp/http/https/tcpmux (port Some(0)), but `max_ports_per_client` check (910-918) gates only tcp/udp/sudp. Fix: increment only when `consumes_port` AND allocated port > 0.
2. **SUDP shared-port release without owner check** (control/proxy.rs:66-68): `handle_close_proxy` removes port from `used_udp_ports` unconditionally; other SUDP proxies may still hold the bound socket → later SUDP registration fails bind probe. Fix: remove only when no other live udp/sudp proxy holds it (same `udp_port_has_other_owner` pattern as unregister_control ~1335-1359 and rollback_port_allocation ~368-372).
3. **Control-disconnect sweep run_id-scoped only** (proxy_ops.rs:1277-1284): old-control cleanup can tear down superseding control's fresh proxies when 10s handoff barrier times out. Fix: pass removing `control_id` through the sweep; skip proxies whose registration generation is newer, or abort sweep when `run_id_to_ctl_tx` entry no longer belongs to this control.
4. **TCP bind async after success response** (proxy_ops.rs:837-845, 1152, 1171-1208): listener bind happens in spawned task after NewProxyResp written; bind failure leaves registered-but-dead proxy holding port. Fix: bind TCP listener synchronously, reject proxy on failure (mirror UDP rollback path); or have spawned task report failure before response written.
5. **tcpmux route conflicts silently overwritten** (proxy_ops.rs:1093-1107 + tcpmux.rs:44-107): `register` result ignored, last-writer-wins; closing proxy deletes live sibling's route. Fix: register returns conflict Result → reject proxy on conflict (mirror `register_http_vhost` 545-575); unregister removes a domain only when stored route still belongs to that proxy.
6. **ProxyManager::remove deletes concurrently re-registered proxy's indexes** (proxy.rs:259-290 vs 151-171): re-check `self.proxies.contains_key(name)` before index cleanup.
7. **update_runtime resurrects removed proxy as phantom by_client entry** (proxy.rs:222-246): re-check `contains_key` before `by_client` insert.
8. **rollback_vhost_conflict removes port without ownership check** (proxy_ops.rs:398-406): only remove when failing proxy actually consumed the port (gate on `consumes_port`).
9. **remove_client vs register race** (proxy.rs:317-330): skip if considered out of scope — evaluate during implementation; if a cheap guard exists, apply it.

**Tests:** proxy registration integration tests (`frp-server/tests/`), `cargo test -p frp-server`.

## Task 6 — Client plugin request-body forwarding [MEDIUM ×2]

**Files:** `frp-client/src/plugin/mod.rs` (read_request_and_build_forward, ~307-412), `frp-client/src/plugin/http.rs` (handle_http_forward, ~174-224)

**Findings:**
1. Shared HTTP/1.1 forward path (used by http2http.rs:52, http2https.rs:77, https2http.rs:122, https2https.rs:137) reads only to first `\r\n\r\n`, discards pre-read body bytes, forwards original Content-Length unmodified → backend blocks forever on POST/PUT. Go frp streams bodies.

2. After header block, drain remaining body (CL or chunked) into the forward before relaying response. Strip hop-by-hop headers (Transfer-Encoding, Connection) — append single `Connection: close` as already done.
