# frp-rs 0.7.1 Release Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:dispatching-parallel-agents for the read-only audit phase, then subagent-driven-development for fix batches. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the current worktree release-ready for frp-rs 0.7.1 with Go frp v0.70.1 compatibility, verified performance/concurrency/memory/network behavior, security hardening, and complete release engineering.

**Architecture:** Move the in-progress review-fix diff onto the already-released `origin/main` base, run six parallel read-only audits, triage findings into disjoint fix batches, then run the full release verification matrix.

**Tech Stack:** Rust workspace (frp-core/frp-client/frp-server/frp-vnet), tokio, Go frp v0.70.1 compatibility scripts, cargo gates.

## Global Constraints

- Base branch: `origin/main` at `18ca230` (v0.7.1 release state); working branch: `codex/0.7.1-release-prep`.
- Preserve the pre-existing uncommitted review-fix diff; do not revert or discard it.
- No new runtime dependencies; no unrelated refactors.
- Gates that must pass before release readiness:
  - `cargo test --workspace --all-features`
  - `cargo clippy --workspace --all-targets --all-features -D warnings`
  - `cargo fmt --all -- --check`
  - `cargo bench --workspace --no-run`
  - `scripts/compat-test.sh` against Go frp v0.70.1
  - Version string `0.7.1` in all crates and release scripts/docs
- Audit agents are read-only: they must not edit files or run cargo builds/tests; they write reports only.
- Fix batches must have disjoint file ownership to avoid parallel-edit conflicts.

### Task 3: Parallel read-only audits (6 domains)

Each audit agent writes a report to `/tmp/frp071-audits/<domain>.md` with severity-tagged findings (`Critical` / `Important` / `Minor`), exact `file:line` references, and no code changes.

- [ ] **Compat audit** — Go frp v0.70.1 wire/config/control parity. Focus: `frp-core/src/{config,protocol,encryption,mux,quic}.rs`, `frp-client/src/{control,work_conn,service,proxy}.rs`, `frp-server/src/control/{login,bridge,mod,nathole}.rs`.
- [ ] **Performance audit** — hot-path allocations, buffering, logging, and copies. Focus: `frp-core/src/{bridge,splice,encryption,mux,protocol}.rs`, `frp-client/src/{work_conn,service,proxy}.rs`, `frp-server/src/{service,ssh_gateway}.rs`.
- [ ] **Concurrency & memory audit** — lock ordering, races, task leaks, bounded queues, and state cleanup. Focus: `frp-server/src/{state,service,handlers,control/*}.rs`, `frp-client/src/{work_conn,service}.rs`, `frp-core/src/{bridge,mux,quic}.rs`.
- [ ] **Network I/O audit** — socket options, splice/zero-copy, TLS/QUIC/WebSocket framing, timeouts, and test harness portability. Focus: `frp-core/src/{splice,quic,mux,bridge}.rs`, `frp-vnet/src/*`, `scripts/compat-test.sh`, `frp-server/tests/common/mod.rs`.
- [ ] **Security audit** — auth validation, OIDC subject generation, TLS defaults, log redaction, bounds/panics, and privilege boundaries. Focus: `frp-server/src/{control/login,control/bridge,handlers,service,ssh_gateway}.rs`, `frp-core/src/{auth,config,encryption}.rs`, `frp-client/src/{control,work_conn}.rs`.
- [ ] **Release engineering audit** — versions, docs, scripts, CI, benchmarks, and test coverage. Focus: `Cargo.toml`, all crate `Cargo.toml`, `frp-core/src/lib.rs`, `scripts/download-frp-rs.sh`, `scripts/download-go-frp.sh`, `CHANGELOG.md`, `README.md`, `.github/workflows/*`, `frp-core/tests/mux.rs`.
